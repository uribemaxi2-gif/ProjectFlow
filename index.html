Responsabilidades por rol

Qué debe hacer cada puesto durante el proyecto.

◈

Project Manager (PM)

Coordinación

1 persona
  • Actúa como contacto principal con el cliente y recoge requisitos.
  • Prioriza el MVP, asigna tareas y verifica fechas y bloqueos.
  • Coordina demostraciones, decisiones y entrega final.
▤

Líder de Frontend

Desarrollo y aseguramiento interno

1 persona
  • Define estructura y criterios de la interfaz.
  • Distribuye el trabajo entre los cuatro desarrolladores.
  • Revisa Pull Requests y calidad visual/accesibilidad.
▦

Desarrolladores Frontend

Desarrollo y aseguramiento interno

4 personas
  • Construyen pantallas, formularios, componentes y navegación.
  • Consumen las API acordadas con backend.
  • Prueban su código, estados de error y diseño responsive.
⌘

Líder de Backend

Desarrollo y aseguramiento interno

1 persona
  • Diseña la arquitectura del servidor y los contratos de API.
  • Divide el trabajo de los cuatro desarrolladores.
  • Revisa lógica, seguridad y calidad del código.
⌁

Desarrolladores Backend

Desarrollo y aseguramiento interno

4 personas
  • Crean endpoints, validaciones y lógica de negocio.
  • Implementan autenticación y permisos cuando corresponda.
  • Escriben pruebas de los servicios e integran la BD.
◫

Responsable de Base de Datos

Desarrollo y aseguramiento interno

1 persona
  • Diseña el MER, modelo relacional y restricciones.
  • Supervisa migraciones, integridad y acceso a datos.
  • Coordina los cambios del esquema con el líder backend.
⊞

Apoyo de BD / Backend

Desarrollo y aseguramiento interno

1 persona
  • Implementa migraciones, datos de prueba y consultas.
  • Ayuda en rendimiento y corrección de errores de BD.
  • Apoya endpoints del backend cuando haya menos carga de datos.
⤴

Representante de Integración

Desarrollo y aseguramiento interno

1 persona
  • Gestiona integración entre frontend, backend y BD.
  • Verifica contratos de API, entornos y versiones integradas.
  • Coordina pruebas internas, despliegue y entrega al QA externo.

⚑
QA externo: cómo trabajar con él

El grupo externo realiza QA formal. Sin embargo, cada desarrollador prueba sus cambios, cada líder revisa el código y el representante de integración valida los flujos antes de enviarlos a QA. No se debe esperar al final para detectar fallas.

Cuatro acuerdos para trabajar mejor

Reglas mínimas recomendadas para un proyecto corto.

01 / VISIBILIDADTablero compartido

Una tarea, una persona responsable y una fecha de término.

02 / CALIDADRevisión por PR

Los cambios se revisan antes de fusionarlos a la rama principal.

03 / COORDINACIÓNReuniones breves

Informar avance, bloqueos y lo siguiente por hacer.

04 / ALCANCEMVP primero

Entregar pocas funcionalidades completas antes que muchas a medias.
